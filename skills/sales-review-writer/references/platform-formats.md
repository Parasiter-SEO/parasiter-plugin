# Platform formats

Same sales logic everywhere (author → problem → solution → bridge → facts → decision → CTA); the format adapts to the platform. Before publishing, look at what already ranks on the platform and copy its native style and limits.

| Platform | Length | Tone | Formatting / limits |
|---|---|---|---|
| Medium, LinkedIn, blog-type platforms | 1,500–2,000+ words | Expert or real-user blog post | Full structure, tables, images, TOC |
| Forums | 1,500+ words; split into post + replies only if the forum has a character limit | Native forum user/expert, first person, friendly, asks for replies | Forum editor (often BBCode), images hosted externally, check keyword filters and moderation; unique title matters most; prepare 2–5 own replies in the thread |
| Reddit / Quora | Short to medium | Genuine question/answer, community voice | No sales voice; follow subreddit rules |
| PDF (upload platforms) | ~3,000 words | Research paper / analysis | Clean, standard document look (no flashy design); few light images; TOC/bookmarks; key benefits and main links on the first screens; mobile-readable; soft CTAs |
| Press release (GlobeNewswire, Access Newswire, etc.) | 2,000–3,000 words | Independent expert/journalist, educational | Neutral language, avoid "best"/hype; facts, comparisons, links to credible sources; images if the editor allows |
| Raisely / fundraising CMS | 1,500+ words (article minimum) | Personal blog of an expert/user | Usually no inline images (use the cover image); emojis, lists, links; compact spacing; line-by-line comparisons |
| Facebook page/group posts | Short | Brand fan / expert | Link + deal in the first lines; visuals; hashtags; series of posts on different benefits |
| Open-book / long-guide platforms | 2,000–3,500 words per chapter | Expert guide / buyer's research | One chapter = one topic; full structure, tables, TOC; chapter title is the page title |
| Document platforms | 2,000–3,000 words | Analytical review written as what it is: a buyer's comparison by the named author | Clean document look, headings, tables, references to real studies; affiliate disclosure stays; never present a promotional review as a peer-reviewed study or invent data |
| Gamma (gamma.app) docs / presentations | 1,200–2,000 words in 8–15 cards | Visual guide | One idea per card: facts card, comparison table card, prices card, FAQ cards, CTA card; short text (40–120 words per card), big headings; Gamma pages render real text, so cards are indexed; links on the product names and the CTA card |
| Prezi (prezi.com) | 800–1,500 words over 10–20 slides | Visual guide / buyer's briefing | **Check indexing first:** a crawler often sees only the page menu and title, not the slide text — search `site:prezi.com "<exact phrase from a slide>"` on a live example before investing; don't recommend Prezi to a user until that check passes. Put the full title, the main query and a 2–3 sentence summary with the link in the **description field** (that part is indexed). 20–40 words per slide; links on the facts, prices and CTA slides and in the description |
| Canva (public design / website links) | 600–1,200 words over 8–15 pages | Visual guide | Text is often rendered as images — check indexing the same way; real text boxes, not text baked into pictures; the title page carries the main query; links on text elements (CTA and prices pages) |
| PDF slides (deck exported to PDF and uploaded to a document host) | 1,200–2,500 words over 12–25 slides | Analytical briefing | Text stays selectable (export from a text editor, not as images); slide 1 = title with the query + one-line summary; a link on the facts, prices and CTA slides (clickable in the PDF); a short text summary in the host's description field |
| Podcast platforms (Firstory, Spotify via RSS) | Episode description 800–1,500 words + 5–10 min script | Host / reviewer voice | Title = the query; description carries quick facts, links and timestamps in the first lines; the same episode syndicated to Spotify is one piece of content, not two |
| Community posts | 1,000–2,000 words | Community member sharing a comparison | Native post, a question to the group at the end; links where the community allows |
| YouTube description | 1,000–3,000 characters | Reviewer | Affiliate link + deal + key selling point in the first 3 lines; then full description, timestamps, hashtags |

## Delivery format by platform

Every article comes the same way, whatever the platform (№31): **formatted in the chat + a `.docx` with the same formatting + images and the cover prompt**, every product name linked. **No `.md` / `.txt` files and no Markdown unless the user asks.** The platform only changes:

| Editor | Platforms (examples) | What changes |
|---|---|---|
| Visual / most editors | Medium, LinkedIn, WordPress, Raisely, Google Sites, HackMD, community editors | nothing — copy from the chat or the .docx |
| Presentation | Prezi, Gamma, Canva, PDF slides | the .docx and the chat text go by slides: "Slide N — Title" heading, text, image; tables become image slides; links are added by hand in Prezi (one line says how) |
| Markdown / BBCode — only on request | HackMD, Dev.to, Reddit, BBCode forums | the source in a code block in addition, when the user asks |
| Plain text / short | Facebook, YouTube description, Quora, podcast description | the text in the chat with links written out in full; the .docx still comes |
| Document | PDF and document hosts | the .docx (export it to PDF) |

Not sure which editor the platform uses? Check the platform's own post editor or a live example (`platform-analyzer`), then pick the row.

Slide template (presentations, in the .docx and the chat):
```
Slide 1 — A vs B: Which One to Buy in 2026        (Heading 2 in the .docx)
  one-line promise of the deck
  [image: cover]
Slide 2 — Quick facts
  price from … · guarantee … · best for … (checked 02.11.2026)
  [image: 01-quick-facts.jpg]
  See today's price → (the words are the link)
…
```

## Titles that rank and get clicks

Personal and experience-based: "Honest Review", "My 90-Day Trial" (only if real), "How I Tested…", "Best … in 2026 — Full Comparison", "[A] vs [B]: Which One to Buy". Include the main keyword. On forums the title must stand out from dozens of similar posts.

## Keep copies

Save every published text (and HTML where possible). Platforms delete posts; a saved copy can be republished elsewhere quickly. On forums only the title must be unique.
