# Posting model — one idea, many findable pieces

A creator's advantage is volume. The model turns one researched idea into pieces for every channel, each made for that platform's search, so one topic has several chances to show up in Google and in-app search.

## The chain (per idea)

| # | Piece | Where | Search job | Made with |
|---|---|---|---|---|
| 1 | Long video (6–15 min) | YouTube | ranks for the main query on YouTube and in Google video results; chapters can show as key moments | `video-seo` package |
| 2 | 3–5 short clips (15–60 s) | YouTube Shorts, Instagram Reels, TikTok, Facebook Reels | the "Short videos" block in Google, in-app search | `video-seo` short package per platform (the keyword in the first line, on-screen text, spoken) |
| 3 | 1–2 pins | Pinterest (Idea / video pin + image pin) | Google Images and Pinterest search | `post-illustrations` (vertical 1000×1500), pin title and description with the query |
| 4 | Text post with the video embedded | Blog / Medium / LinkedIn / Facebook / Substack | a text page that can rank for the query and gives the video an indexed link | `sales-review-writer` brand mode (the creator's voice) or a plain how-to |
| 5 | Community answer | Reddit / Quora / forum, only where the rules allow sharing one's own content | "Discussions and forums" | a real answer first, the link only if allowed |
| 6 | Hub update | Creator's site / link page | links the new pieces so they are found and indexed | — |

## Cadence (sized to time)

| Time per week | Model |
|---|---|
| 2–3 h | 1 idea / week: 1 long or 3 shorts + 1 pin + hub link |
| 5–8 h | 2 ideas / week: 1 long video + 4–6 shorts + 2 pins + 1 text post |
| 10+ h | 3–4 ideas / week, full chain for the strongest idea |

Consistency beats volume: the plan never holds more than the creator's time.

## What every piece carries

- The main query in the title or first line, said aloud in the first seconds of a video, and on screen.
- A clear next step: the long video, the hub, the offer or the affiliate link (disclosed).
- Logged in the journal with its query, so it gets checked and tracked.
